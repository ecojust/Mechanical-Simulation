# 验证方法与精度边界

客户端用于检查装配方案、尺寸和基本功能。结果只适用于输入的尺寸、公差、碰撞体与物理参数，不构成实际打印件、机加工件或电子硬件的合格证明。验证报告中的警告需要单独处理，不能把“没有阻断错误”理解为所有项目均已通过。

## 坐标和单位

- 世界坐标采用右手系，Y 轴向上。位置、尺寸、位移和行程为 **mm**；旋转为 **度**，使用 XYZ 欧拉角。
- 参数化零件的位置是其局部几何中心。榫卯和套筒的插入轴为局部 Y 轴。
- 电压用 V，电阻用 Ω，电流用 A，质量用 kg，力用 N。
- 弹簧刚度使用 N/mm，阻尼使用 N·s/m；求解时需进行毫米与米的换算。
- Blender 源素材采用 1 Blender 单位 = 1 mm。GLB 显示副本按导出清单的毫米尺寸恢复，不能直接把 GLB 默认单位当作实物米数。

## 尺寸、接触与运动

参数化方榫采用实体盒，方榫槽由四个实体壁构成贯穿孔，不把整个外包围盒当作实心块。碰撞检查使用旋转后的凸体或有向包围盒；同轴榫头可以沿孔移动，横向移动到壁面时会产生干涉。允许零间隙接触与判断实体穿透是两件事，数值容差不应作为制造公差使用。

每次位置或角度变化都检查旧姿态到目标姿态的中间采样，以平移、角度扫掠和尺寸变化估算顶点运动上界，将单步控制在 0.25 mm 以内，降低跨越薄壁时只检查终点造成的漏检风险。单次操作若需要超过 20,000 个采样会被拒绝，需要减小步长。该方法属于离散路径检查，不是数学上保证无漏检的连续碰撞检测。极薄结构、高速运动、大角度转动及近乎贴合的曲面，需要缩小操作步长并使用更精确的 CAD 或网格接触检查。

榫卯尺寸需要同时考虑孔与榫的公差。以单个方向的全宽为例：

```text
最小尺寸余隙 = (孔名义宽度 − 孔公差) − (榫名义宽度 + 榫公差)
```

这是全宽差；居中配合时单侧间隙约为其一半。位姿偏移、旋转和有效插入深度还会改变实际接触情况，不能只看这个差值。负余隙表示最坏公差组合存在过盈风险。正余隙也不自动意味着插入深度、同轴性或防晃动要求满足。

界面中的最小余隙取候选配合对的最不利单侧余隙，并非所有曲面之间的全局最短距离。没有候选配合对时该值为空。圆销与圆套在平行同轴方向采用圆径和横向偏移计算余隙；异轴或其他圆形接触使用 16 边保守碰撞代理，可能提前报告干涉。独立弹簧不参与实体碰撞检查；按压按钮总成使用整体包络检查外部干涉，内部机构依赖预设行程模型。

固定属性阻止用户移动该零件。它不是有限元中的材料或边界条件。视觉隐藏、透视显示和爆炸显示都不应被理解为卸载零件或修改其实际装配状态。

### 原始手柄和显示副本

GLB 保留可视形状，复杂模型的碰撞预检采用保守包围体。因此：

- 包围体重叠只提示可能存在干涉；空心套筒、壳体、相互嵌套的组件可能产生误报。
- 包围体分离可排除该包围体之间的接触，但不能证明行程、旋锁、回弹和焊点空间均通过验证。
- 显示网格简化可能改变边缘与小孔，应在原始 `.blend` 上复核曲面、实体连通性、非流形边和最小净空。
- 导入的外观组件没有自动获得真实关节、弹簧材料或电气端子语义；不能用预设演示零件的求解结果替代该组件的验证。

## 按压、弹簧与回弹

弹簧采用带阻尼的一维弹性模型，依据输入刚度、质量、外力与行程计算位移及速度。基本关系是 `F = kx`，采用隐式 Euler 积分和细分时间步，并施加行程限位。按压开关在压缩位移达到设定触发点时改变电路状态，释放后由模型中的回位力和阻尼产生回弹。

该模型没有计算偏心载荷、屈曲、弹簧圈接触、塑性、疲劳、温升、真实静摩擦或材料粘弹性，也不是任意机构的多体动力学求解器。行程限制和可视动画不能替代检查实际弹簧并圈高度、开关过行程、套筒接触和键帽偏摆。

当前素材没有厂商确认的弹簧刚度和实测触发行程。默认参数用于演示，使用实际零件时至少测量自由长度、预压量、工作载荷、最大压缩和触发点。未测量的参数应在验证记录中标为假设。

## 电路验证

导线按端子建立拓扑，验证关注电源、常开触点、阻性负载与直流回路。只有连线构成有效路径且开关达到触发条件时，灯才应得到供电。悬空端子、缺失元件、开路、短接电源及不支持的连接需要在结果中处理。

求解使用直流改进节点分析，支持阻性负载串并联与独立电源。理想电源并联等无法唯一求解的约束会报告错误。界面的总电流为各电源支路电流绝对值之和，多个电源时不能把它当作某一根导线的电流。

灯的电气行为采用简化阻性负载；这不是完整 LED 二极管或白炽灯热模型。不能用此结果确认 LED 极性、正向压降、额定功率、电池内阻、短路保护、导线载流量、焊点可靠性或 ESP32 GPIO 电平安全。机械导线显示也不提供绝缘厚度、实际弯曲半径和导线与壳体之间的接触求解。

## 推荐验收流程

### 参数化装配回归

1. 固定底板，建立一个方榫槽和尺寸略小的方榫；检查静止状态和尺寸余隙。
2. 沿局部 Y 轴缓慢插入，确认贯穿孔不会被当作实心块。
3. 横移榫头，使其越过槽壁；动作应被拒绝，保留旧姿态并指出阻挡零件。
4. 在孔内旋转榫头，再测试一个终点没有碰撞、但路径穿墙的大步移动。
5. 改成孔小于榫、最坏公差负余隙、尺寸不合法等情况，检查验证不能显示为无条件通过。
6. 对圆销、套筒、弹簧等近似碰撞体读取对应限制，再测试接触与插入；使用原始模型复核重要边缘。

### 按压与电路回归

1. 在无按压状态检查开关断开，灯保持关闭。
2. 将电源、开关、电阻与灯连接为回路，施加按压力并观察触发点。
3. 松手观察回弹和开关断开，确认灯状态随电路而变化。
4. 删除一段导线，应得到开路；短接电源正负极，应报告短路，不能当成正常亮灯。
5. 改变电压、负载电阻、弹簧刚度、阻尼和行程，观察数值是否随输入改变。
6. 保存工程、重新载入，再验证参数、位置和端子连线保持一致。

### pureTV 实物前验证

遵循 [AGENTS.md](../AGENTS.md) 的顺序，先单键、再四键底座、再合壳。每阶段保存静止、触发、压到底和回弹状态，记录插销余隙、触发点、最大压缩、螺丝头净空、线束空间及任何碰撞位置。额外验证偏心按压、圆弧装入和旋出路径。

先试印一套键帽、套筒和底座，测量加工偏差、实际行程、按压力、回弹与重复拆装，再校正客户端参数。完整手柄还需要验证上盖开孔、下壳容积、PCB、USB 插头、线束和焊点。

每次记录应包含工程文件、模型来源或校验值、名义尺寸、公差假设、物理参数来源、观察姿态、计算结果及实测结果。结构或参数修改后重新运行验证，旧报告只适用于当时保存的工程。

## 可复现的默认示例验证

仓库提供 [默认示例数值验证记录](demo-verification.json)，仅覆盖参数化示例，未包含原始手柄复杂网格的精确装配证明。重新生成：

```bash
npx vite-node scripts/verify-demo.ts
```

该记录核对默认单侧最不利余隙、插入路径、横向与旋转阻挡、按压前后电路电流，以及释放后的弹簧残余位移和速度。修改默认示例、算法或参数后应重新生成，不能沿用旧记录作为新版本结论。


## 自定义组件的验证边界

上传GLB/STL仅提供显示几何。功能类型、代理尺寸、局部轴与中心，以及该类型要求的交互参数决定实际检验；缺少参数的组件被标记为仅预览，阻止仿真及相关运动。配置完整后也会保留代理与外观网格仍需核对的提示。配合族、最大插入深度和最小单侧余隙在运动路径的每个采样姿态检查，不能靠终点正确跳过装配障碍。

原始手柄集合与拆分对象都有显式结构预览类型；用户可在右侧声明功能并配置代理，不自动从名称推断。当前自定义旋锁代理只接受标准两耳45°尺寸；复杂自定义槽形需要后续专用碰撞模型。详细字段、坐标约定和文件限制见 [组件定义](COMPONENTS.md)。MCP与界面共享同一个类型规则及几何/物理引擎，协议说明见 [MCP接入](MCP.md)。


## 多零件机构与撞针触点

组合组件按角色同步活动子件和可视弹簧，运动由声明的固定/活动代理逐步校验。弹簧沿压缩轴的显示包络长度必须匹配自由长度，使缩放与中心位移共同保持固定端；不同长度的弹簧不能直接共享同一个自由长度参数。

开关闭合由撞针端点、固定触发点、法向间距、有效半径和允许压入量共同决定，不根据旧行程阈值或人为强制pressedIds闭合机制成员。触点和触发圆盘须落在对应子件尺寸包络内，仍不构成触点位于网格表面的证明。配置方法与公式见 [多零件功能机构](MECHANISMS.md)。
